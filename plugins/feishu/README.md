# feishu 插件

飞书 / Lark 私聊渠道：通过长连接接收单聊消息，以流式卡片回复。每个飞书企业自建应用对应角色的一个账号，应用凭据保存在插件自己的存储里。

创建应用、订阅事件和手动验收的完整步骤见 [TESTING.md](TESTING.md)。

---

## 应用权限

在飞书开发者后台的「权限管理」为应用开通以下权限（名称以后台实际显示为准）：

| 权限 | 用途 | 缺少时 |
|---|---|---|
| `im:message.p2p_msg:readonly` | 读取用户发给机器人的单聊消息 | 收不到消息 |
| `im:message:send_as_bot` | 以应用的身份发消息 | 无法回复 |
| `im:message` | 读取被引用的消息、撤回失败的流式卡片 | 看不到被引用内容 |
| `im:resource` | 获取与上传图片或文件资源 | 收发不了图片和文件 |
| `cardkit:card:write` | 创建与更新卡片（流式卡片） | 回复退回普通卡片 |
| `contact:user.base:readonly` | 按 open_id 读取发送者的名称和头像 | 小手机里发送者没有昵称（显示 open_id），头像保持占位图标 |

开通或调整权限后，需要在「版本管理与发布」发布新版本才会生效。

## 发送者昵称与头像

飞书消息事件只带发送者的 open_id。插件在收到私聊消息后，于后台调用通讯录接口（`GET /open-apis/contact/v3/users/:user_id`）取该发送者的名称和头像，不阻塞消息投递：

- 名称由插件缓存，写进之后消息的发送者昵称（`sender_name`）；刚认识的发送者第一条消息还没有昵称。
- 头像交给宿主缓存（`ctx.avatars`），显示在小手机的聊天页、会话列表和身份设置里。
- 名称与头像每 7 天随该发送者的下一条消息重新获取一次。
- 没有 `contact:user.base:readonly` 权限时，日志里记一条警告，消息照常收发，到期后再试。
