# 插件四层重构验收补齐

状态：实施中。关联 #898；承接 2026-10-22 四层方案及 P6–P8b 的后续修订。

## 范围

补齐总验收发现的六项缺口：manifest 的 `replaces` / `conflicts`、已有插件发版前单次 patch、统一插件生命周期契约、`pnpm new-plugin <id> [--ui]`、后端 RPC 名称生成与前端调用核对、现状文档。此收尾不发布 SDK / 桌面版本、不恢复发布 cron，也不代替冻结安装包的升级验收。

## 选择与边界

比较了独立提出的 SDK fake 生命周期扩展与生产宿主契约执行两种方案。选择复用生产 `PluginKernel`、绑定器和注册表；已有 fake context 会在关闭时清空自身表，不能作为生产卸载无残留的证据。纯 SDK 插件 wheel 隔离测试继续单独保留。

统一契约由仓库测试支持代码装配真实宿主，按所有 manifest 枚举真实插件 setup。只替换模型、网络、进程等外部 I/O 边界；不替换目标 setup、服务或宿主释放代码。使用现有开发/CI 宿主依赖环境，无需再建立三十份宿主 wheel 环境：包依赖隔离已由原有独立作业负责。新增插件未配置必要 fixture 必须失败，不能默认 skip。

对每个插件验证：有效配置下声明的 Key 由目标真实提供；冷启动与重载后的注册和事件处理顺序一致；停用后作用域、提供者、事件、RPC、工具、服务及目标任务回到基线。观察必须发生在 fixture 应急清理之前。进程资源按现有跨代保留/最终关闭规则验证。渠道或不可卸载插件验证整体拒绝代内重载、原实例保持可用，再验证最终关闭。需要分支配置才能注册的能力使用明确命名的额外场景。

RPC 名称以实际后端注册处的有限字符串/常量/表为唯一来源，生成各插件 TypeScript 常量及联合类型，前端实际消费它们。提取器只支持可证明有限的形状；无法解析时在具体源位置报错，不建立人工例外表或任意 Python 解释器。真实生命周期观测的注册集合与生成清单交叉检查。前端检查依类型识别 RPC 调用，解析有限名称及依赖目标；无限字符串报错。background handle 与 service contract 分别核对自身提供方，不混进后端 RPC 清单。名称检查不宣称验证所有 payload。

脚手架生成 API 4 / SDK 4 插件、后端最小 RPC、包元数据、测试和说明；`--ui` 增加标准前端入口、SDK 组件及生成 RPC 常量。拒绝非法 ID 和已有目录，不覆盖文件。生成物用同一 manifest 校验、RPC 生成、打包和真实 setup/stop 路径验证。

manifest 关系字段从 schema、解析、静态准入一直传到现有 SDK graph。启停导致 provider 选择变化时，宿主用同一 graph 计划扩展现有排空事务，包含受影响的硬依赖与已用 optional 消费者。保留取消、回滚与 D14；不改变 graph 的冲突优先级，不增加 Key、phase、层或生产 Kernel API。

## 验证

新增机制本身需要失败证明：缺 provide、卸载残留、顺序变化、未更新消费者、不可卸载闭包错误执行；RPC 错名、未覆盖注册和无限动态调用；脚手架拒绝覆盖及生成包可用。按新增行为和直接调用者运行定向检查，保留既有 CI。全部 manifest 必须有成功契约结果，不能用源码扫描替代真实 setup。

已有插件从重构前基线起内容有变化的只升一次 patch，新插件保留初始版本；消费方精确依赖及锁文件同步。最终证据写入交付记录，历史方案中的被替代设计明确链接到最终实现。
