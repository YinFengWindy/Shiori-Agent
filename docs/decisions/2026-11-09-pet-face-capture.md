# 2.5D 桌宠的电脑摄像头面捕

状态：维护者已确认电脑摄像头输入，以及 AI 实际播报期间嘴部由语音优先控制。基于独立 2.5D 形象插件继续实现；现有包格式和精灵图依赖边界不变。

## 行为

2.5D 插件设置提供摄像头选择、手动开启／停止和中性姿态校准。角色跟随头部左右转动、俯仰、侧倾、左右独立眨眼和张嘴。只保存设备与镜像偏好；开启状态和校准基准留在本次运行内，应用重启后默认关闭。

实际 TTS 的 `playback_id` 存在时，嘴部始终使用已接入的 RMS，包括音频内的静音片段；此时头部和双眼仍跟随摄像头。播放结束后回到当前有效面捕口型。没有新鲜人脸数据时平滑恢复待机，摄像头可以继续等待重新入镜。摄像头中断或推理失败显示错误并结束本次采集。

视频只在当前 surface 和本地 Worker 中流动，不进入 Python、聊天消息或持久化存储。只有用户开启且形象已显示时才调用 `getUserMedia`，明确 `audio: false`；准备中的隐藏候选不申请摄像头。隐藏、关闭、切换到精灵图、停用插件或销毁窗口都释放 tracks、采样和 Worker，迟到回调不能重新开启采集。普通隐藏可以保留本次会话的开启意图，重新显示时重新建立实例；旧实例先停止，新实例才接手。

## 所有权与接口

- `pet_2d` UI/background 保存偏好和面捕控制状态，通过现有后台 RPC 控制当前可见呈现实例。
- surface 拥有 `MediaStream`、视频帧采样、session 和滤波。共享呈现控制器只补可选的可见性与自定义消息回调，不复制窗口生命周期。
- 插件 Worker 拥有 MediaPipe Face Landmarker。单脸、CPU 推理、约 18 FPS，最多一帧在途；忙时跳过新帧，不积累延迟。传入的 `ImageBitmap` 在处理完毕后释放。
- 数值样本携带 session、顺序和时间信息，包含 yaw/pitch/roll、左右眼开度和嘴部开度。renderer 保留最新输入，沿既有 RAF 插值；每帧数据不经过 React state 或后端。
- renderer 扩展为左右独立眼睑参数，头部姿态映射到现有分层深度与颈部旋转。幅度受限，不能将 2.5D 图层变形宣称为完整三维侧脸重建。

## 选择本地 Web Worker

比较了浏览器 MediaPipe Worker 与插件私有 Python/OpenCV 进程。Web 方案利用浏览器现成的摄像头 ID、设备枚举与流生命周期，避免为本次功能引入另一套平台运行环境。Python 路径可复用托管服务，但现行托管安装仅支持 Windows x64，默认设备索引也不足以实现可靠的摄像头选择。

JavaScript/WASM 固定为 `@mediapipe/tasks-vision` 1.2.2。模型使用 Google 官方版本 1 的 `face_landmarker.task`，哈希和来源记在插件 assets 的 NOTICE 中，随构建分发；运行时不拉取 CDN。

宿主只补通用资源装载：`?url` 原样资源、`?worker&url` 独立 classic Worker，内置生产资源映射到固定 `renderer-dist/assets`，外部插件走已有 token 与内容快照。CSP 明确允许本地插件资源、Blob Worker bootstrap 和 WebAssembly；不开放远程脚本或普通 `unsafe-eval`。该前端运行契约以 SDK 4.1.3 标识，不增加 capability、phase、层或既有 Protocol 的必需方法。

## 本次范围

不包含手机面捕、外部面捕软件、标准 Cubism、全身捕捉、音素口型或直播推流。现有语音和直播助手继续拥有自己的唯一播报队列。

按维护者要求不扩展测试或独立审查轮次。交付检查限于相关类型、lint、生产与插件包构建，以及一次不调用摄像头的离线 Worker／模型初始化检查；真实摄像头由用户手动开启，硬件效果需如实区分。
