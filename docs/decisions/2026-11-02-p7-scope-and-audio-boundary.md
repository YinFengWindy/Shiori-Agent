# P7 实施范围与通用音频边界

维护者于 2026-11-02 确认，P7（#908，属于 #898）按 #962–#967 六个单元推进，汇总到一个功能分支与总 PR 后统一验收。

## 范围

除单 frontend 入口、RPC/事件命名空间、通信生命周期和热重载重挂外，P7 接收 P6b 留下的两项：内置 Drift skill 随 proactive 插件分发，以及角色会话 key 的共享格式实现。角色数据路径、会话 key 格式与 UI 偏好存储键保持不变。保留现有组件与布局。

实施依赖为：单入口试点 #964 → 剩余插件迁移 #965；#965 和通信收口 #966 → 热重载验收 #967。会话 key #962、Drift 资源 #963 不互相阻塞。安装器裁剪、信任存储迁移、内核 LOC 门禁及恢复桌面发版仍属于 P8。

## 修订 D12 的语音部分

通用麦克风采集、设备枚举、音频解码与播放留在宿主。插件拥有自身业务策略，共用纯工具按实际消费者复用。

当前桌宠通过通用原生音频能力连接可选择的 ASR/TTS 服务，GPT-SoVITS 的试听也使用相同播放原语。把这些通用实现整体搬入 sensevoice_asr 或 gpt_sovits_tts，会使其他提供方依赖这两个具体插件。因此撤销原 D12 中机械迁移整个 renderer voice 目录的要求，不创建独立的“搬语音”步骤；保留多提供方、试听、取消和资源释放的验收。

## 单入口与运行环境

单 frontend 入口通过具名导出提供 UI、background、surface。统一的是包入口、分发与加载契约；主窗口、常驻后台与 surface 窗口仍各自挂载所需贡献。模块求值不得隐式启动所有贡献，宿主也不因迁移而失去激活失败回滚、授权或旧代资源隔离。
