# SDK 版本规则：代际、兼容线与兼容更新

状态：2026-11-05 用户明确确认，适用于 Shiori SDK 的 Python/npm 同步版本。修订四层重构 D22；不改变插件、内部客户端库或桌面自身的版本语义。未授权发布标签、覆盖发布物或合并 PR。

## 规则

SDK 的 `A.B.C` 使用项目自定义的兼容含义：

- `A` 表示整体 SDK 代际。
- `B` 可包含破坏性 API 变更，包括删除接口、修改已有 Key/Protocol 的必需契约。升级前检查调用者并提供迁移说明。
- `C` 用于同一 `A.B` 兼容线内的兼容修复、功能与迁移，不改变该线的既有调用契约。新增必需方法属于破坏性变更，不能只提高 `C`。

这是非标准 SemVer 的兼容承诺。版本仍使用既有三段数值排序、预发布比较和显式区间语法，不修改通用比较器，不添加隐式上限或自动 breaking 判定。manifest 格式仍为 `api: 4`，独立于 SDK 版本。

新插件默认声明 `sdk: ">=4.1.0 <4.2.0"`，Python 使用 `shiori-sdk>=4.1.0,<4.2.0`，frontend/npm peer 使用 `>=4.1.0 <4.2.0`。已核对跨线兼容的插件可以明确覆盖多条线，例如 `>=4.0.0 <4.2.0`。只检查缺失 Key 不能替代版本范围；范围也不能替代 API 调用者核查。

npm/Python 继续按各自原有规则解释 `^4.1.0`、`<5` 等范围，它们不会因为本规则自动收紧到 4.1 线。安装说明与仓库声明使用明确上下限。已经发布的外部插件若声明 `>=4.0.0`，宿主仍按这个声明比较，不将其偷偷重解释为 `4.0.x`；作者需要按实际测试的兼容线重新发布声明。

## 本次迁移

SDK 源版本改为 **4.1.0**。删除 `PROCESSES.mcp`、SDK MCP 类型与 decoder 的实现决定不变，不恢复兼容壳；客户端进入内部库，见 [MCP 客户端归属](2026-11-05-mcp-client-boundary.md)。MCP、Browser Use、Computer Use 及内部客户端库要求 `>=4.1.0,<4.2.0`。其他已核对未用删除 API 的插件保留 4.0 下限并显式限制 `<4.2.0`。

此前未合入的 SDK 5.0 方案从未发布；选择 4.1.0 不构成回退已分发版本。已发布 SDK 4.0 和更早的标签、wheel/tarball、历史记录不可覆盖。本次不因 SDK 规则变化修改插件或内部客户端自身版本。

版本唯一来源仍为 `packages/sdk/python/shiori_sdk/_version.py`，npm、宿主和 host-testing 精确 pin 与其一致。既有发布工具只检查版本排序、pin、变更记录以及已分发版本不可复用；它没有 API 语义 diff，不负责决定某次变更该提升哪一位。

## 验证与边界

用实际包准入证明 4.1 的兼容更新可被明确区间接受、4.2 被拒绝；仓库声明检查同时覆盖 manifest、Python/test extra 与 frontend peer。保持对旧宽范围的原有解释。SDK 和客户端的确切产物在私有环境安装验证，不从公共索引取得同名内部包。

不增加 capability、Key、phase、运行时层或兼容 wrapper。四层重构的扩展面冻结仍有效；同一兼容线不能以新增必需方法绕过兼容承诺，下一条兼容线可以显式整理拆开的接口。
